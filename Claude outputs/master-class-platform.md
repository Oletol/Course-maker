# Мастер-класс «Своя платформа курса»

Передача состояния на 22 ноября 2026 года.

## Что это

Руководство, по которому преподаватели иностранных языков собирают при помощи ИИ
собственный сайт курса с регистрацией участников, интерактивными заданиями и
экраном преподавателя. Сокращённая версия оболочки Olto, без оценок и хранения
прогресса.

Аудитория мастер-класса — преподаватели без опыта программирования.
Обучение ведётся на английском языке. Участники работают с DeepSeek или Qwen.

## Структура руководства

Семь шагов. 01 что нужно, 02 база данных, 03 правила для ИИ, 04 сборка,
05 публикация, 06 если не работает, 07 проверка.

## Архитектура платформы, которую собирают участники

Три части, разделение принципиальное.

```
index.html      механика, собирается один раз и больше не меняется
content.js      содержание курса, правится без ИИ
assets/img/     изображения
assets/audio/   аудиозаписи
```

Объект `COURSE` в `content.js`:

```js
const COURSE = {
  settings: {
    courseTitle: "", unitTitle: "",
    audience: "",      // одно предложение, для кого модуль
    outcome: "",       // результат модуля целиком
    teacherName: "", primaryColour: "", accentColour: ""
  },
  sections: [
    { id: "", title: "", intro: "", image: "", imageAlt: "", audio: "", tasks: [] }
  ]
};
```

Три типа заданий, поле `type`:

- `gap` — заполнение пропуска. Элемент: `sentence` с тремя подчёркиваниями,
  `answer`, `accept` (массив), `hint`
- `choice` — выбор одного из четырёх. Элемент: `question`, `options` (4 строки),
  `correctIndex`, `why` (4 строки, по одной на вариант)
- `match` — сопоставление пар нажатием. Элемент: `left`, `right`

## Firebase

Коллекции: `participants` (запись регистраций), `groups` (группы курса),
`teachers` (документ с идентификатором, равным почте преподавателя).

Правила вставляются один раз и больше не редактируются, подстановок в них нет.
Преподаватель опознаётся через `exists()` по почте, группы проверяются через
`exists()` по коду. Запись в `participants` разрешена только с существующим
кодом группы, чтение только преподавателю, изменение и удаление запрещены всем.
Коллекция `teachers` закрыта на запись отовсюду, новые преподаватели
добавляются вручную в консоли.

Порядок настройки, девять шагов: проект, Firestore, Authentication с Email
и Password, пользователь на вкладке Users, коллекция `teachers`, правила,
регистрация веб-приложения, копирование `firebaseConfig` в `my-config.txt`.

## Сборка, пять запросов

1. Каркас, `index.html` плюс пример `content.js`
2. Регистрация, читает группы из базы
3. Экран преподавателя, вход по почте, управление группами, таблица регистраций
4. Механика трёх типов заданий
5. Содержание, только `content.js`

Первые четыре наращивают `index.html` примерно до тысячи строк, дальше он не
меняется. Пятый запрос повторяется чаще всего и выдаёт короткий файл данных.

## Принятые решения и причины

- Один файл отвергнут: с аудио и изображениями репозиторий всё равно становится
  папкой, а совместное хранение механики и содержания приводит к обрывам ответа
  к четвёртому кругу
- Код группы не секретный, обучающийся выбирает группу из выпадающего списка.
  Настоящей защиты от посторонних записей нет, страница открыта; реальный
  механизм это Firebase App Check, он вынесен за рамки мастер-класса
- Отдельный тип задания на аудирование не нужен, аудио стоит над подразделом,
  вопросы делаются типом `choice`
- Записи, оценки и прогресс не хранятся сознательно

## Что проверено на живых моделях

Запрос 1 прогнан в Qwen дважды.

Первый прогон: в `index.html` зашито учебное предложение (из-за того, что поля
`audience` в структуре не было), по ссылке Teacher вызывался `alert`.

Второй прогон, после правок: всплывающее окно и зашитый текст исчезли, но
`settings.audience` не использовался, на его место подставлен `outcome`,
результат печатался дважды. Заголовок вкладки остался словом Course, ссылка
Teacher сделана через `href="#"`.

После этого требование к экрану Welcome переписано на перечисление полей
поимённо, заголовок вкладки вынесен в отдельный пункт, запрет на смену адреса
назвал `href="#"` прямо. Третий прогон ещё не сделан.

Вывод, важный для методики: модель ошибается там, где требование описывает
смысл, а не имя поля.
