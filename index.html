Своя платформа курса

Your own course platform

Как собрать сайт курса с регистрацией участников и интерактивными заданиями при помощи ИИ. Нужны только браузер, аккаунт GitHub и база данных Firebase.

How to build a course website with participant registration and interactive tasks using AI. All you need is a browser, a GitHub account and a Firebase database.

Шаг 01

Что нужно

Весь сайт — это один файл index.html. Его пишет ИИ по Вашему заданию, а Вы его только публикуете. Ничего устанавливать не нужно.

Аккаунт GitHub

Здесь будет жить сайт. Регистрация на github.com, адрес почты нужно подтвердить.

Доступ к ИИ

Любая модель, которая умеет писать код. Откройте одну новую пустую переписку и работайте в ней до конца.

База данных Firebase

Сюда придут записи о регистрации участников. Настройка — шаг 02.

Одна переписка — одна платформа. Если начать новую, ИИ потеряет и правила, и текущий файл, и начнёт собирать всё заново. Перед каждым следующим шагом сохраняйте последнюю рабочую версию файла отдельно, чтобы неудачный ответ стоил одной вставки, а не всей работы.

Step 01

What you need

The whole website is a single index.html file. The AI writes it from your brief and you simply publish it. Nothing has to be installed.

A GitHub account

This is where the site will live. Sign up at github.com and confirm your e-mail address.

Access to an AI

Any model that writes code. Open one new empty conversation and stay in it to the end.

A Firebase database

This is where registration records arrive. Setting it up is step 02.

One conversation per platform. Starting a new one loses both the rules and the current file, and the AI begins again from nothing. Before each new step, save the last working version of the file somewhere separate, so a bad answer costs you one paste rather than the whole build.

Шаг 02

База данных

Делается один раз, до сборки. На выходе нужны файл my-config.txt с настройками подключения и преподавательский вход.

  1. Откройте console.firebase.google.com и войдите в аккаунт Google.
  2. Нажмите «Создать проект». Имя задайте латиницей, например my-course. Аналитику подключать не нужно.
  3. В левом меню, в разделе Product categories, откройте Databases & Storage и выберите в выпавшем списке Firestore, он в группе NoSQL. Нужен именно Firestore, а не Realtime Database, это две разные базы данных. Нажмите кнопку создания базы. Режим выберите производственный (production). Регион возьмите ближайший — сменить его потом нельзя.
  4. В левом меню, в разделе Product categories, откройте Security и выберите Authentication. Нажмите кнопку начала работы, в списке способов входа выберите Email/Password и включите верхний переключатель. Второй, Email link, включать не нужно.
  5. Перейдите на вкладку Users, нажмите Add user, введите свою рабочую почту и пароль, который больше нигде не используется. Это Ваш преподавательский вход.
  6. Вернитесь в Firestore, на вкладку с данными, и нажмите Start collection. Идентификатор коллекции — teachers. Идентификатор документа — Ваша почта, та же самая, что на предыдущем шаге, знак в знак. Добавьте одно поле с именем name, тип string, значение — Ваше имя. Сохраните.
  7. Откройте вкладку Rules, удалите всё, что там есть, вставьте текст ниже и нажмите Publish. Менять в нём ничего не нужно.
Правила доступа
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isTeacher() {
      return request.auth != null
        && exists(/databases/$(database)/documents/teachers/$(request.auth.token.email));
    }

    match /teachers/{email} {
      allow read: if request.auth != null && request.auth.token.email == email;
      allow write: if false;
    }

    match /groups/{code} {
      allow read: if true;
      allow write: if isTeacher();
    }

    match /participants/{docId} {
      allow create: if request.resource.data.keys().hasOnly(['displayName', 'groupCode', 'platformId', 'createdAt'])
        && request.resource.data.displayName is string
        && request.resource.data.displayName.size() >= 2
        && request.resource.data.displayName.size() <= 40
        && exists(/databases/$(database)/documents/groups/$(request.resource.data.groupCode));
      allow read: if isTeacher();
      allow update, delete: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

Эти правила вставляются как есть и больше не открываются никогда. В них нет ни Вашей почты, ни кодов групп, ни других значений, которые пришлось бы подставлять. Всё, что меняется со временем, живёт в самой базе.

Читать список зарегистрировавшихся может только тот, чья почта лежит документом в коллекции teachers. Дописать себя туда через платформу нельзя, коллекция закрыта на запись, новые преподаватели добавляются только Вами и только в консоли. Проверки на то, что вошёл хоть кто-нибудь, здесь было бы мало, потому что завести себе аккаунт в Вашем проекте может любой.

Группы хранятся в коллекции groups и заводятся позже, на экране преподавателя. Зарегистрироваться можно только в ту группу, которая там есть, это проверяют правила. Добавили группу — она работает сразу, без правок правил и без переустановки платформы.

  1. В левом меню нажмите Settings и выберите General. Прокрутите страницу вниз до раздела Your apps и нажмите значок с угловыми скобками, это веб-приложение. Имя приложения любое, Firebase Hosting подключать не нужно, затем нажмите Register app.
  2. На экране появится блок firebaseConfig. Скопируйте его целиком в текстовый файл и сохраните под именем my-config.txt. Если файл потеряется, этот же блок всегда лежит в Settings, General, раздел Your apps.

Блок выглядит примерно так, значения в нём будут Ваши собственные.

Образец firebaseConfig
const firebaseConfig = {
  apiKey: "AIzaSyB7hK2mNp...",
  authDomain: "my-course-2f41c.firebaseapp.com",
  projectId: "my-course-2f41c",
  storageBucket: "my-course-2f41c.firebasestorage.app",
  messagingSenderId: "408271936502",
  appId: "1:408271936502:web:9c3b1aa7e5d04f82"

Копируйте его целиком, вместе со словами const firebaseConfig = в начале и закрывающей фигурной скобкой с точкой с запятой в конце. Строки выше, которые начинаются со слова import или с двух косых черт, не нужны.

Значение apiKey в этом блоке — не пароль, а идентификатор проекта, поэтому он спокойно лежит в открытом коде сайта. Доступ к данным определяют правила.

Step 02

The database

Done once, before building. What you need at the end is a my-config.txt file holding the connection settings, and a teacher sign-in.

  1. Open console.firebase.google.com and sign in with a Google account.
  2. Click Create a project. Give it a plain name such as my-course. Analytics is not needed.
  3. In the left menu, under Product categories, open Databases & Storage and choose Firestore from the list that appears, in the NoSQL group. It must be Firestore and not Realtime Database, which is a different database. Click the button that creates the database. Choose production mode. Pick the region closest to you — it cannot be changed later.
  4. In the left menu, under Product categories, open Security and choose Authentication. Click the button that starts it, pick Email/Password in the list of sign-in methods and turn on the first switch. The second one, Email link, is not needed.
  5. Open the Users tab, click Add user, and enter your work e-mail and a password you use nowhere else. This is your teacher sign-in.
  6. Go back to Firestore, to the data tab, and click Start collection. The collection id is teachers. The document id is your e-mail, exactly the one from the previous step, character for character. Add one field called name, of type string, with your name as its value. Save.
  7. Open the Rules tab, delete everything in it, paste the text below and click Publish. Nothing in it needs changing.
Security rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isTeacher() {
      return request.auth != null
        && exists(/databases/$(database)/documents/teachers/$(request.auth.token.email));
    }

    match /teachers/{email} {
      allow read: if request.auth != null && request.auth.token.email == email;
      allow write: if false;
    }

    match /groups/{code} {
      allow read: if true;
      allow write: if isTeacher();
    }

    match /participants/{docId} {
      allow create: if request.resource.data.keys().hasOnly(['displayName', 'groupCode', 'platformId', 'createdAt'])
        && request.resource.data.displayName is string
        && request.resource.data.displayName.size() >= 2
        && request.resource.data.displayName.size() <= 40
        && exists(/databases/$(database)/documents/groups/$(request.resource.data.groupCode));
      allow read: if isTeacher();
      allow update, delete: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

These rules are pasted as they are and never opened again. They hold no e-mail of yours, no group codes, nothing you would have to substitute. Everything that changes over time lives in the database itself.

Only the person whose e-mail sits as a document in the teachers collection can read the list of registrations. Nobody can add themselves there through the platform, the collection is closed to writing, and new teachers are added by you alone, in the console. Checking merely that somebody is signed in would not be enough here, because anyone can create an account in your project.

Groups live in the groups collection and are created later, on the teacher screen. A learner can register only into a group that exists there, and the rules enforce it. Add a group and it works at once, with no edit to the rules and no redeployment of the platform.

  1. In the left menu click Settings and choose General. Scroll down to the Your apps section and click the angle brackets icon, which stands for a web app. Any app name will do, Firebase Hosting is not needed, then click Register app.
  2. A firebaseConfig block appears on screen. Copy the whole of it into a text file and save it as my-config.txt. If the file goes missing, the same block always sits in Settings, General, the Your apps section.

The block looks roughly like this, with your own values in it.

What firebaseConfig looks like

Copy the whole of it, including the words const firebaseConfig = at the start and the closing brace with its semicolon at the end. The lines above it that begin with import or with two slashes are not needed.

The apiKey value in that block is not a password but a project identifier, which is why it can sit openly in the site's code. Access is decided by the rules.

Шаг 03

Правила для ИИ

Этот блок вставляется в начало каждого запроса, без изменений. Он удерживает результат в одном файле, который работает на телефоне и который можно править, не читая код.

Правила
ПРАВИЛА. Соблюдай их во всех ответах в этой переписке.

1. Присылай один готовый HTML-файл. Стили внутри элемента style, скрипт внутри элемента script, в том же файле. Никогда не присылай больше одного файла.
2. Только чистые HTML, CSS и JavaScript. Без React, Vue, jQuery, npm, сборки и любых фреймворков.
3. Сначала телефон. Страница должна работать на телефоне в вертикальном положении, без горизонтальной прокрутки.
4. Язык интерфейса — английский.
5. Никогда не используй символы стрелок в интерфейсе. Пиши словами — Next, Back, Continue, Check.
6. Основной текст не меньше 16 пикселей. Контраст текста к фону не ниже 4,5 к 1.
7. Всеми элементами можно пользоваться с клавиатуры, клавишами Tab и Enter.
8. Никогда не обозначай верный и неверный ответ только цветом. Всегда дублируй словами.
9. Без картинок из интернета. Если нужно изображение, рисуй его в SVG или средствами CSS.
10. Все мои настройки и всё содержание держи в именованных объектах в самом начале скрипта, чтобы я мог их править, не читая остальной код.
11. При любой правке присылай файл целиком, с первой строки до последней. Никогда не присылай фрагмент, заплатку или указание вставить что-то самостоятельно.
12. В ответе только блок кода. Без пояснений до и после него.
Step 03

Rules for the AI

This block goes at the start of every request, unchanged. It keeps the result in one file that works on a phone and that you can edit without reading the code.

Rules
RULES. Apply all of these to every answer in this conversation.

1. Return one complete HTML file. The CSS inside a style element and the JavaScript inside a script element, in that same file. Never give me more than one file.
2. Plain HTML, CSS and JavaScript only. No React, Vue, jQuery, npm, build step or frameworks of any kind.
3. Mobile first. It must work on a phone held upright, with no horizontal scrolling.
4. The interface language is English.
5. Never use arrow characters in the interface. Use words such as Next, Back, Continue, Check.
6. Body text at least 16 pixels. Text contrast at least 4.5 to 1 against its background.
7. Every control must be usable with the keyboard alone, with Tab and Enter.
8. Never mark an answer right or wrong by colour alone. Always say it in words as well.
9. No images from the internet. If a picture is needed, draw it in SVG or with CSS.
10. Keep all of my settings and all content in named objects at the very start of the script, so that I can edit them without reading the rest of the code.
11. Whenever you change anything, return the whole file again, from the first line to the last. Never send a fragment, a patch, or an instruction to insert something myself.
12. Answer with the code block only. No explanation before or after it.

Каркас

Запрос 1
Ты разработчик интерфейсов. Я преподаватель и код читаю плохо, поэтому всё должно работать без моих правок.

Собери каркас платформы курса. Заданий пока не нужно.

Требования.
1. Один HTML-файл с четырьмя экранами, которые показываются по одному — Welcome, Registration, Unit, Finish. Переключение экранов делай в JavaScript, скрывая и показывая секции. Не создавай отдельных страниц и не меняй адрес.
2. В самом начале скрипта объект SETTINGS с полями courseTitle, unitTitle, outcome, teacherName, primaryColour, accentColour. Весь остальной код берёт значения из него. Заполни его по моему заданию на курс.
3. Закреплённая полоса сверху на каждом экране — название курса слева, отметка шага справа, вида Step 1 of 4. Отметка обновляется при смене экрана.
4. Экран Welcome — название курса, одно предложение о том, для кого модуль, результат модуля целиком и кнопка Start.
5. Экран Registration — пока только заголовок, одно предложение-заглушка и кнопка Continue. Форму добавим позже.
6. Экран Unit — название модуля и пустой элемент с id tasks, внутри только комментарий TASKS GO HERE.
7. Экран Finish — два предложения с поздравлением, отдельное предложение о том, что ничего не сохранено и модуль можно пройти снова, и кнопка Back to start.
8. Оформление на пользовательских свойствах CSS, построенных из двух цветов в SETTINGS. Много воздуха, один шрифт, никакого декора, который сам несёт смысл.
9. Над каждым крупным блоком кода одна строка комментария простыми словами, что этот блок делает.

Присылай файл целиком.

Прежде чем публиковать, найдите в ответе три вещи — объект SETTINGS, надпись на кнопке Start и комментарий TASKS GO HERE. Поменяйте в SETTINGS название курса и убедитесь, что заголовок изменился.

Регистрация

Запрос 2
Добавь в этот файл регистрацию участников. Всё, что уже работает, оставь как есть.

Используй Firebase Firestore, подключённый с CDN Google в варианте compat, чтобы всё работало в одном HTML-файле без установки. Вот мои настройки, вставь их ровно так, как написано, ничего внутри не меняя.

ВСТАВЬТЕ СЮДА СОДЕРЖИМОЕ ФАЙЛА my-config.txt

Требования.
1. При открытии экрана Registration прочитай коллекцию groups. У каждого документа идентификатор — это код группы, а поле name — её название для обучающегося.
2. Вместо заглушки сделай форму из двух полей. Display name — текстовое, обязательное, от 2 до 40 знаков. Group — выпадающий список, обязательный, собранный из прочитанных групп. В списке показывай name, а в базу записывай код, то есть идентификатор документа. Первым пунктом поставь пустое значение, чтобы группа выбиралась осознанно.
3. Если коллекция groups пуста или не прочиталась, не показывай пустой список. Покажи одно предложение о том, что группы ещё не заведены, и кнопку Try again.
4. Под полями одно предложение простыми словами о том, что именно отправляется и кто это увидит, и флажок согласия, без которого продолжить нельзя. Подпись флажка должна быть понятна сама по себе.
5. Проверяй поля в JavaScript до отправки. Ошибку показывай словами рядом с тем полем, к которому она относится. Не опирайся на цвет и не используй всплывающие окна.
6. При отправке записывай ровно один документ в коллекцию participants с полями displayName, groupCode, platformId и createdAt. Константу platformId объяви в начале скрипта. Для createdAt возьми серверную отметку времени Firestore.
7. Платформа никогда ничего не изменяет и не удаляет в коллекции participants и не читает её на этом экране.
8. Пока идёт отправка, кнопка заблокирована и подписана Sending. При успехе переходи на экран Unit. При ошибке покажи одно предложение о том, что регистрацию записать не удалось, дай кнопку Try again и всё равно пропусти дальше, на экран Unit, потому что сбой базы не должен останавливать занятие.
9. Каждый вызов, который обращается к сети или к хранилищу браузера, оберни в try и catch.
10. Не храни в браузере ничего об обучающемся дольше текущего посещения.

Присылай файл целиком.

Пока групп нет, форма скажет об этом, и это правильно. Заведите одну группу прямо в консоли, в коллекции groups, чтобы проверить регистрацию сейчас. Дальше группы добавляются на экране преподавателя. Зарегистрируйтесь один раз, найдите свою запись в консоли, затем попробуйте имя из одной буквы — должен быть отказ словами, рядом с полем.

Задания

Запрос 3. Заполнение пропусков
Добавь в файл первое задание. Всё, что уже работает, оставь как есть.

Тип задания — заполнение пропуска, по одному предложению за раз, с ответом сразу.

1. Вместо комментария TASKS GO HERE поставь задание.
2. В начале скрипта объяви массив TASK_1. У каждого элемента поля sentence, где пропуск обозначен тремя подчёркиваниями, answer, accept — массив других написаний и форм, которые тоже считаются верными, и hint, который указывает на правило, но не выдаёт слово.
3. Показывай по одному предложению, с полем ввода на месте пропуска, кнопкой Check и кнопкой Hint. Над заданием простая строка вида Item 2 of 5.
4. По кнопке Check сравнивай введённое с answer и accept, убрав пробелы по краям и не различая регистр. Если верно — одно короткое предложение и кнопка Next. Если неверно — оставь введённое, покажи подсказку и дай вторую попытку. После второй попытки покажи ответ и одно предложение о том, в чём была ошибка.
5. Обратная связь называет ошибку, а не просто помечает её. Не Incorrect, а, например, That form is the past simple and this sentence needs the present perfect.

Шаг 05

Публикация

Всё делается в браузере на github.com. Ничего устанавливать не нужно.

Первый раз

  1. На github.com нажмите плюс справа сверху и выберите New repository.
  2. Имя задайте строчными латинскими буквами и дефисами, например my-english-course. Отметьте Public и нажмите Create repository.
  3. На пустой странице нажмите ссылку creating a new file.
  4. Назовите файл ровно index.html. Вставьте в большое поле весь файл от ИИ. Нажмите Commit changes и подтвердите.
  5. Откройте вкладку Settings, затем Pages в левом меню. В разделе Source выберите Deploy from a branch, ветку main, папку root, и нажмите Save.
  6. Подождите пару минут и обновите страницу Pages. Сверху появится ссылка вида https://ИМЯ.github.io/my-english-course/. Откройте её на телефоне.

Каждое обновление

  1. Откройте репозиторий, нажмите на index.html, затем на значок карандаша.
  2. Выделите всё в поле и удалите. Вставьте новый файл целиком.

Пустая страница почти всегда означает, что файл назван не index.html или не задан источник в разделе Pages. Страница, которая не меняется, — это память браузера, и лечится обновлением с зажатым Shift.

Step 05

Publishing

Everything happens in the browser on github.com. Nothing has to be installed.

The first time

  1. On github.com click the plus sign at the top right and choose New repository.
  2. Name it in lower-case letters and hyphens, for example my-english-course. Tick Public and click Create repository.
  3. On the empty page, click the link called creating a new file.
  4. Name the file exactly index.html. Paste the whole file from the AI into the large box. Click Commit changes and confirm.
  5. Open the Settings tab, then Pages in the left menu. Under Source choose Deploy from a branch, the main branch and the root folder, then click Save.
  6. Wait a couple of minutes and reload the Pages screen. A link appears at the top, of the form https://NAME.github.io/my-english-course/. Open it on a phone.

Every update

  1. Open the repository, click index.html, then the pencil icon.
  2. Select everything in the box and delete it. Paste the whole new file.
  3. Click Commit changes and wait a minute.
  4. Reload the live page with the Shift key held down, so the browser takes the new version rather than the one it remembers.

A blank page almost always means the file is not named index.html or the source was never set under Pages. A page that refuses to change is the browser's memory, and a reload with Shift held fixes it.
