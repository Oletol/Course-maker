Своя платформа курса

Your own course platform

Как собрать сайт курса с регистрацией участников и интерактивными заданиями при помощи ИИ. Нужны только браузер, аккаунт GitHub и база данных Firebase.

How to build a course website with participant registration and interactive tasks using AI. All you need is a browser, a GitHub account and a Firebase database.

Шаг 01

Что нужно

Платформа состоит из двух файлов и одной папки. Механику пишет ИИ, содержание курса пишете Вы, медиа кладёте сами.

Устройство платформы
index.html      механика — экраны, задания, вход, таблица
content.js      содержание — модуль, подразделы, тексты заданий
assets/img/     изображения
assets/audio/   аудиозаписи

Разделение здесь главное. index.html собирается один раз и больше не меняется. Всё, что Вы будете править из года в год, лежит в content.js обычным текстом в кавычках, и чтобы поправить задание, код открывать не нужно.

Аккаунт GitHub

Здесь будет жить сайт. Регистрация на github.com, адрес почты нужно подтвердить.

Доступ к ИИ

Любая модель, которая умеет писать код. Откройте одну новую пустую переписку и работайте в ней до конца.

База данных Firebase

Сюда придут записи о регистрации участников. Настройка — шаг 02.

Одна переписка — одна платформа. Если начать новую, ИИ потеряет и правила, и текущие файлы, и начнёт собирать всё заново. Перед каждым следующим шагом сохраняйте последнюю рабочую версию отдельно, чтобы неудачный ответ стоил одной вставки, а не всей работы.

Step 01

What you need

The platform is two files and one folder. The AI writes the mechanics, you write the course content, and you add the media yourself.

How the platform is built
index.html      mechanics — screens, tasks, sign-in, table
content.js      content — the unit, its sections, the task texts
assets/img/     images
assets/audio/   audio recordings

This split is the point. index.html is built once and then left alone. Everything you will revise from year to year sits in content.js as plain text between quotation marks, so changing a task never means opening the code.

A GitHub account

This is where the site will live. Sign up at github.com and confirm your e-mail address.

Access to an AI

Any model that writes code. Open one new empty conversation and stay in it to the end.

A Firebase database

This is where registration records arrive. Setting it up is step 02.

One conversation per platform. Starting a new one loses both the rules and the current files, and the AI begins again from nothing. Before each new step, save the last working version somewhere separate, so a bad answer costs you one paste rather than the whole build.

Шаг 02

База данных

Делается один раз, до сборки. На выходе нужны файл my-config.txt с настройками подключения и преподавательский вход.

  1. Откройте console.firebase.google.com и войдите в аккаунт Google.
  2. Нажмите «Создать проект». Имя задайте латиницей, например my-course. Аналитику подключать не нужно.
  3. В левом меню, в разделе Product categories, откройте Databases & Storage и выберите в выпавшем списке Firestore, он в группе NoSQL. Нужен именно Firestore, а не Realtime Database, это две разные базы данных. Нажмите кнопку создания базы. Режим выберите производственный (production). Регион возьмите ближайший — сменить его потом нельзя.
  4. В левом меню, в разделе Product categories, откройте Security и выберите Authentication. Нажмите кнопку начала работы, в списке способов входа выберите Email/Password и включите верхний переключатель. Второй, Email link, включать не нужно.
  5. Перейдите на вкладку Users, нажмите Add user, введите свою рабочую почту и пароль, который больше нигде не используется. Это Ваш преподавательский вход.
  6. Вернитесь в Firestore, на вкладку с данными, и нажмите Start collection. Идентификатор коллекции — teachers. Идентификатор документа — Ваша почта, та же самая, что на предыдущем шаге, знак в знак. Добавьте одно поле с именем name, тип string, значение — Ваше имя. Сохраните.
  7. Откройте вкладку Rules, удалите всё, что там есть, вставьте текст ниже и нажмите Publish. Менять в нём ничего не нужно.
Правила доступа
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isTeacher() {
      return request.auth != null
        && exists(/databases/$(database)/documents/teachers/$(request.auth.token.email));
    }

    match /teachers/{email} {
      allow read: if request.auth != null && request.auth.token.email == email;
      allow write: if false;
    }

    match /groups/{code} {
      allow read: if true;
      allow write: if isTeacher();
    }

    match /participants/{docId} {
      allow create: if request.resource.data.keys().hasOnly(['displayName', 'groupCode', 'platformId', 'createdAt'])
        && request.resource.data.displayName is string
        && request.resource.data.displayName.size() >= 2
        && request.resource.data.displayName.size() <= 40
        && exists(/databases/$(database)/documents/groups/$(request.resource.data.groupCode));
      allow read: if isTeacher();
      allow update, delete: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

Эти правила вставляются как есть и больше не открываются никогда. В них нет ни Вашей почты, ни кодов групп, ни других значений, которые пришлось бы подставлять. Всё, что меняется со временем, живёт в самой базе.

Читать список зарегистрировавшихся может только тот, чья почта лежит документом в коллекции teachers. Дописать себя туда через платформу нельзя, коллекция закрыта на запись, новые преподаватели добавляются только Вами и только в консоли. Проверки на то, что вошёл хоть кто-нибудь, здесь было бы мало, потому что завести себе аккаунт в Вашем проекте может любой.

Группы хранятся в коллекции groups и заводятся позже, на экране преподавателя. Зарегистрироваться можно только в ту группу, которая там есть, это проверяют правила. Добавили группу — она работает сразу, без правок правил и без переустановки платформы.

  1. В левом меню нажмите Settings и выберите General. Прокрутите страницу вниз до раздела Your apps и нажмите значок с угловыми скобками, это веб-приложение. Имя приложения любое, Firebase Hosting подключать не нужно, затем нажмите Register app.
  2. На экране появится блок firebaseConfig. Скопируйте его целиком в текстовый файл и сохраните под именем my-config.txt. Если файл потеряется, этот же блок всегда лежит в Settings, General, раздел Your apps.

Блок выглядит примерно так, значения в нём будут Ваши собственные.

Образец firebaseConfig
const firebaseConfig = {
  apiKey: "AIzaSyB7hK2mNp...",
  authDomain: "my-course-2f41c.firebaseapp.com",
  projectId: "my-course-2f41c",
  storageBucket: "my-course-2f41c.firebasestorage.app",
  messagingSenderId: "408271936502",
  appId: "1:408271936502:web:9c3b1aa7e5d04f82"
};

Копируйте его целиком, вместе со словами const firebaseConfig = в начале и закрывающей фигурной скобкой с точкой с запятой в конце. Строки выше, которые начинаются со слова import или с двух косых черт, не нужны.

Значение apiKey в этом блоке — не пароль, а идентификатор проекта, поэтому он спокойно лежит в открытом коде сайта. Доступ к данным определяют правила.

Step 02

The database

Done once, before building. What you need at the end is a my-config.txt file holding the connection settings, and a teacher sign-in.

  1. Open console.firebase.google.com and sign in with a Google account.
  2. Click Create a project. Give it a plain name such as my-course. Analytics is not needed.
  3. In the left menu, under Product categories, open Databases & Storage and choose Firestore from the list that appears, in the NoSQL group. It must be Firestore and not Realtime Database, which is a different database. Click the button that creates the database. Choose production mode. Pick the region closest to you — it cannot be changed later.
  4. In the left menu, under Product categories, open Security and choose Authentication. Click the button that starts it, pick Email/Password in the list of sign-in methods and turn on the first switch. The second one, Email link, is not needed.
  5. Open the Users tab, click Add user, and enter your work e-mail and a password you use nowhere else. This is your teacher sign-in.
  6. Go back to Firestore, to the data tab, and click Start collection. The collection id is teachers. The document id is your e-mail, exactly the one from the previous step, character for character. Add one field called name, of type string, with your name as its value. Save.
  7. Open the Rules tab, delete everything in it, paste the text below and click Publish. Nothing in it needs changing.
Security rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isTeacher() {
      return request.auth != null
        && exists(/databases/$(database)/documents/teachers/$(request.auth.token.email));
    }

    match /teachers/{email} {
      allow read: if request.auth != null && request.auth.token.email == email;
      allow write: if false;
    }

    match /groups/{code} {
      allow read: if true;
      allow write: if isTeacher();
    }

    match /participants/{docId} {
      allow create: if request.resource.data.keys().hasOnly(['displayName', 'groupCode', 'platformId', 'createdAt'])
        && request.resource.data.displayName is string
        && request.resource.data.displayName.size() >= 2
        && request.resource.data.displayName.size() <= 40
        && exists(/databases/$(database)/documents/groups/$(request.resource.data.groupCode));
      allow read: if isTeacher();
      allow update, delete: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

These rules are pasted as they are and never opened again. They hold no e-mail of yours, no group codes, nothing you would have to substitute. Everything that changes over time lives in the database itself.

Only the person whose e-mail sits as a document in the teachers collection can read the list of registrations. Nobody can add themselves there through the platform, the collection is closed to writing, and new teachers are added by you alone, in the console. Checking merely that somebody is signed in would not be enough here, because anyone can create an account in your project.

Groups live in the groups collection and are created later, on the teacher screen. A learner can register only into a group that exists there, and the rules enforce it. Add a group and it works at once, with no edit to the rules and no redeployment of the platform.

  1. In the left menu click Settings and choose General. Scroll down to the Your apps section and click the angle brackets icon, which stands for a web app. Any app name will do, Firebase Hosting is not needed, then click Register app.
  2. A firebaseConfig block appears on screen. Copy the whole of it into a text file and save it as my-config.txt. If the file goes missing, the same block always sits in Settings, General, the Your apps section.

The block looks roughly like this, with your own values in it.

What firebaseConfig looks like

  projectId: "my-course-2f41c",

  appId: "1:408271936502:web:9c3b1aa7e5d04f82"

Copy the whole of it, including the words const firebaseConfig = at the start and the closing brace with its semicolon at the end. The lines above it that begin with import or with two slashes are not needed.

The apiKey value in that block is not a password but a project identifier, which is why it can sit openly in the site's code. Access is decided by the rules.

Шаг 03

Правила для ИИ

Этот блок вставляется в начало каждого запроса, без изменений. Он удерживает механику отдельно от содержания и не даёт модели присылать куски, которые пришлось бы сращивать вручную.

Правила
ПРАВИЛА. Соблюдай их во всех ответах в этой переписке.

1. У платформы два файла. index.html — механика. content.js — содержание курса. В одном ответе присылай один файл, тот, который я назвал, и всегда целиком, с первой строки до последней.
2. Механика ничего не знает о конкретном курсе. Все заголовки, тексты, задания и пути к медиа она берёт из объекта COURSE, объявленного в content.js. В index.html не должно остаться ни одного учебного текста. Служебные надписи интерфейса — названия кнопок, заголовки экранов, сообщения об ошибках — наоборот, пиши прямо в index.html по-английски, в содержание они не выносятся.
3. Когда я прошу содержание, присылай только content.js и не трогай index.html. Когда я прошу правку механики, присылай только index.html.
4. Только чистые HTML, CSS и JavaScript. Без React, Vue, jQuery, npm, сборки и любых фреймворков. Стили внутри элемента style, скрипт внутри элемента script, оба в index.html. Элемент style ставь в head, а все элементы script последними внутри body, после всей разметки.
5. Сначала телефон. Страница должна работать на телефоне в вертикальном положении, без горизонтальной прокрутки.
6. Язык интерфейса — английский.
7. Никогда не используй символы стрелок в интерфейсе. Пиши словами — Next, Back, Continue, Check.
8. Основной текст не меньше 16 пикселей. Контраст текста к фону не ниже 4,5 к 1.
9. Всеми элементами можно пользоваться с клавиатуры, клавишами Tab и Enter.
10. Никогда не обозначай верный и неверный ответ только цветом. Всегда дублируй словами.
11. Изображения и звук бери только из папки assets по относительному пути, который задан в содержании. Ничего из интернета. Декоративную графику рисуй в SVG или средствами CSS.
12. Никогда не используй всплывающие окна браузера — alert, confirm и prompt. Любое сообщение и любой вопрос рисуй прямо на странице.
13. Никогда не присылай фрагмент, заплатку или указание вставить что-то самостоятельно.
14. Если ответ не помещается целиком, не сокращай код, не выбрасывай части и не пиши «остальное без изменений». Продолжай писать файл, пока он не кончится, а если ответ оборвётся, я попрошу продолжить.
15. В ответе только блок кода. Без пояснений до и после него.
Step 03

Rules for the AI

This block goes at the start of every request, unchanged. It keeps the mechanics apart from the content and stops the model sending pieces you would have to splice together by hand.

Rules
RULES. Apply all of these to every answer in this conversation.

1. The platform has two files. index.html holds the mechanics. content.js holds the course content. Send one file per answer, the one I named, and always in full, from the first line to the last.
2. The mechanics know nothing about any particular course. Every heading, text, task and media path comes from the COURSE object declared in content.js. Not one line of teaching text may stay in index.html. Interface wording, on the other hand — button labels, screen headings, error messages — is written straight into index.html in English and never moved into the content.
3. When I ask for content, send content.js only and leave index.html alone. When I ask for a change to the mechanics, send index.html only.
4. Plain HTML, CSS and JavaScript only. No React, Vue, jQuery, npm, build step or frameworks of any kind. The CSS inside a style element and the JavaScript inside a script element, both in index.html. Put the style element in the head and every script element last inside the body, after all the markup.
5. Mobile first. It must work on a phone held upright, with no horizontal scrolling.
6. The interface language is English.
7. Never use arrow characters in the interface. Use words such as Next, Back, Continue, Check.
8. Body text at least 16 pixels. Text contrast at least 4.5 to 1 against its background.
9. Every control must be usable with the keyboard alone, with Tab and Enter.
10. Never mark an answer right or wrong by colour alone. Always say it in words as well.
11. Take images and sound only from the assets folder, by the relative path given in the content. Nothing from the internet. Draw decorative graphics in SVG or with CSS.
12. Never use the browser's pop-up windows, that is alert, confirm and prompt. Draw every message and every question on the page itself.
13. Never send a fragment, a patch, or an instruction to insert something myself.
14. If an answer does not fit, do not shorten the code, drop parts or write "the rest is unchanged". Keep writing the file until it ends, and if the answer is cut off I will ask you to continue.
15. Answer with the code block only. No explanation before or after it.

Запрос 1. Каркас

index.html
Ты разработчик интерфейсов. Я преподаватель и код читаю плохо, поэтому всё должно работать без моих правок.

Собери каркас платформы курса. Пришли два файла, по одному в двух сообщениях подряд — сначала index.html, потом content.js с примером заполнения.

Требования к index.html.
1. Четыре экрана, которые показываются по одному — Welcome, Registration, Module, Finish. Переключение делай в JavaScript, скрывая и показывая секции. Не создавай отдельных страниц и никогда не меняй адрес страницы, в том числе не используй ссылки вида href="#".
2. Подключи content.js обычным тегом script. Оба тега script поставь последними внутри body, после всей разметки, сначала content.js, потом твой скрипт. Если COURSE не загрузился, покажи вместо пустой страницы одно предложение о том, что файл content.js не найден и должен лежать рядом с index.html.
3. Заголовок вкладки браузера бери из settings.courseTitle.
4. Закреплённая полоса сверху — settings.courseTitle слева, название текущего подраздела справа.
5. Экран Welcome выводит ровно эти пять значений, каждое по одному разу и в этом порядке: settings.courseTitle, settings.unitTitle, settings.audience, settings.outcome, settings.teacherName. Ни одно из них не выводи дважды и не подставляй вместо другого. Ниже кнопка Start, в самом низу маленькая неброская ссылка Teacher.
6. Экран Registration — заголовок, одно предложение-заглушка и кнопка Continue. Ссылка Teacher на этом шаге ещё никуда не ведёт и ничего не делает, но адрес страницы при нажатии на неё меняться не должен.
7. Экран Module. Слева или сверху, в зависимости от ширины экрана, список подразделов из COURSE.sections с отметкой пройденных. Рядом содержимое выбранного подраздела — его заголовок, вступительный текст, затем изображение и аудиоплеер, если у подраздела заданы поля image и audio, затем место под задания с комментарием TASKS GO HERE. Внизу кнопки Back и Next, которые ведут по подразделам, а с последнего — на экран Finish.
8. Отметка пройденного подраздела держится только в памяти страницы. Ничего не сохраняется, при перезагрузке всё начинается заново.
9. Экран Finish — два предложения с поздравлением, предложение о том, что ничего не сохранено и модуль можно пройти снова, и кнопка Back to start.
10. Оформление на пользовательских свойствах CSS, построенных из цветов в COURSE.settings. Много воздуха, один шрифт, никакого декора, который сам несёт смысл.
11. Над каждым крупным блоком кода одна строка комментария простыми словами.

Требования к content.js.
12. Файл объявляет одну константу COURSE и больше ничего. Структура такая.

const COURSE = {
  settings: {
    courseTitle: "",
    unitTitle: "",
    audience: "",      // одно предложение, для кого этот модуль
    outcome: "",       // результат модуля целиком
    teacherName: "",
    primaryColour: "",
    accentColour: ""
  },
  sections: [
    { id: "", title: "", intro: "", image: "", imageAlt: "", audio: "", tasks: [] }
  ]
};

13. Поля image, imageAlt и audio необязательные. Если они есть, это относительные пути вида assets/img/market.jpg и assets/audio/dialogue.mp3.
14. Заполни его по моему заданию на курс, по одному подразделу на каждый пункт из списка подразделов, с пустым массивом tasks.

  1. Соберите у себя на компьютере папку курса. В ней index.html, content.js и папка assets с вложенными img и audio.

  1. Откройте репозиторий, нажмите на нужный файл, затем на значок карандаша.
  2. Выделите всё в поле и удалите. Вставьте новую версию файла целиком.
  3. Нажмите Commit changes и подождите минуту.
  4. Обновите живую страницу с зажатой клавишей Shift, чтобы браузер взял новую версию, а не ту, которую запомнил.

Как добавить аудио или изображение

  1. Откройте в репозитории папку assets/audio или assets/img, нажмите Add file, затем Upload files и перетащите свой файл.
  2. Имя файла задайте строчными латинскими буквами, без пробелов, например unit1-dialogue.mp3. Пробелы и кириллица в именах приводят к ссылкам, которые не открываются.
  3. Откройте content.js и впишите путь в поле нужного подраздела, например audio: "assets/audio/unit1-dialogue.mp3". Плеер появится сам.

Пустая страница почти всегда означает, что файл назван не index.html или не задан источник в разделе Pages. Если страница открылась, но всё содержание пропало, значит не загрузился content.js — проверьте, что он лежит рядом с index.html, а не внутри папки. Страница, которая не меняется, — это память браузера, и лечится обновлением с зажатым Shift.

Step 05

Publishing

Everything happens in the browser on github.com. Nothing has to be installed.

The first time

  1. Put the course folder together on your computer. It holds index.html, content.js and an assets folder with img and audio inside it.
  2. On github.com click the plus sign at the top right and choose New repository. Name it in lower-case letters and hyphens, for example my-english-course. Tick Public and click Create repository.
  3. Click Add file, then Upload files. Drag in the contents of the course folder, that is both files and the assets folder, rather than the outer folder itself. Click Commit changes.
  4. Open the Settings tab, then Pages in the left menu. Under Source choose Deploy from a branch, the main branch and the root folder, then click Save.
  5. Wait a couple of minutes and reload the Pages screen. A link appears at the top, of the form https://NAME.github.io/my-english-course/. Open it on a phone.

Every update

  1. Open the repository, click the file you need, then the pencil icon.
  2. Select everything in the box and delete it. Paste the whole new version of the file.
  3. Click Commit changes and wait a minute.
  4. Reload the live page with the Shift key held down, so the browser takes the new version rather than the one it remembers.

Adding audio or an image

  1. Open assets/audio or assets/img in the repository, click Add file, then Upload files, and drag your file in.
  2. Name the file in lower-case letters with no spaces, for example unit1-dialogue.mp3. Spaces and non-Latin letters in file names produce links that do not open.
  3. Open content.js and write the path into the field of the section you want, for example audio: "assets/audio/unit1-dialogue.mp3". The player appears by itself.

A blank page almost always means the file is not named index.html or the source was never set under Pages. If the page opens but all the content is missing, content.js did not load: check that it sits next to index.html rather than inside a folder. A page that refuses to change is the browser's memory, and a reload with Shift held fixes it.

Если не работает

Три запроса на обычные сбои. Править код руками не нужно ни в одном из случаев.

Что-то работает не так
Файл, который ты прислал, работает неправильно.

Я ожидал: одно предложение
Происходит вот что: что именно видно и где

Ничего не переделывай и не трогай то, что уже работает. Найди самую мелкую причину, исправь только её и пришли исправленный файл целиком. После блока кода одним предложением скажи, что было сломано.
Ответ оборвался
Твой ответ оборвался на середине. Последняя строка, которую я вижу, —

вставьте последнюю целую строку

Step 06

If it breaks

Three requests for the ordinary failures. In none of these cases do you edit the code by hand.

Something works wrongly
The file you sent does not work properly.

What I expected: one sentence
What actually happens: what exactly you see, and where
Screen and button: name them

Do not redesign anything and do not touch what already works. Find the smallest cause, fix only that, and send the corrected file in full. After the code block, in one sentence, say what was broken.
The answer was cut off
Your answer stopped in the middle. The last line I can see is

paste the last complete line

Continue from exactly that point. Do not start again and do not repeat what you have already sent. When you finish, write DONE on its own line.
A rule was broken
You have broken one of the rules I gave you at the start of this conversation.

The rule: quote it word for word
Where it is broken: name the screen or the element

Fix it throughout the file, not only where I pointed, and send the whole file again.
Шаг 07

Проверка

Пройдите платформу на телефоне и отметьте каждый пункт. Всё, что здесь перечислено, видно без чтения кода.

  • Результат модуля виден до первого задания, понятными обучающемуся словами.
  • Форма регистрации говорит, что отправляется и кто это увидит, до того как что-то введено.
  • Группа выбирается из списка, а не вводится вручную.
  • Новая группа, заведённая на экране преподавателя, сразу появляется в списке при регистрации.
  • Любое задание проходится с одной клавиатуры, без мыши.
  • Неверный ответ получает обратную связь, которая называет ошибку, а не только помечает её.
  • Каждый неверный вариант в задании на выбор — ошибка, которую делают настоящие обучающиеся.
  • Верный вариант не самый длинный.
  • Платформа работает на телефоне в вертикальном положении, без прокрутки в сторону.
  • Ничего на экране не понятно только по цвету.
  • Нигде в интерфейсе нет символов стрелок.
  • Обучающемуся сказано, что ничего не сохраняется.
  • Список зарегистрировавшихся не открывается без входа. Проверено в приватном окне, после выхода из аккаунта.
  • Примеры звучат как то, что человек действительно сказал бы.
  • Язык заданий соответствует уровню из задания на курс.
  • Текст задания можно поправить, открыв только content.js, не касаясь index.html.
Step 07

Final check

Go through the platform on a phone and tick every line. Everything listed here is visible without reading any code.

  • The unit outcome is visible before the first task, in words a learner understands.
  • The registration form says what is sent and who will see it, before anything is typed.
  • The group is chosen from a list rather than typed.
  • A new group created on the teacher screen appears at once in the list on the registration form.
  • Every task can be completed with the keyboard alone, without a mouse.
  • A wrong answer gets feedback that names the error rather than merely marking it.
  • Every wrong option in the multiple choice is a mistake real learners make.
  • The correct option is not the longest one.
  • The platform works on a phone held upright, with no sideways scrolling.
  • Nothing on screen is understood by colour alone.
  • There are no arrow characters anywhere in the interface.
  • The learner is told that nothing is saved.
  • The list of registrations cannot be reached without signing in. Checked in a private window, after signing out.
  • The examples sound like something a person would actually say.
  • The language of the tasks matches the level in the course brief.
  • A task's text can be changed by opening content.js alone, without touching index.html.
