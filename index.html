Path B. The ready shell

What a path A platform looks like can be seen in a live example: that file is what a model produced in the lesson.

The third section, Materials, carries on from path B and shows how to fill the ready shell with your own course.

Both paths need a GitHub account and a free Firebase project. Nothing has to be paid for: the free limits are more than a teaching group uses.

Шаг 02

База данных

Делается один раз, до сборки. На выходе нужны файл my-config.txt с настройками подключения и преподавательский вход.

  1. Откройте console.firebase.google.com и войдите в аккаунт Google.
  2. Нажмите «Создать проект». Имя задайте латиницей, например my-course. Аналитику подключать не нужно.
  3. В левом меню, в разделе Product categories, откройте Databases & Storage и выберите в выпавшем списке Firestore, он в группе NoSQL. Нужен именно Firestore, а не Realtime Database, это две разные базы данных. Нажмите кнопку создания базы. Режим выберите производственный (production). Регион возьмите ближайший — сменить его потом нельзя.
  4. В левом меню, в разделе Product categories, откройте Security и выберите Authentication. Нажмите кнопку начала работы, в списке способов входа выберите Email/Password и включите верхний переключатель. Второй, Email link, включать не нужно.
  5. Перейдите на вкладку Users, нажмите Add user, введите свою рабочую почту и пароль, который больше нигде не используется. Это Ваш преподавательский вход.
  6. Вернитесь в Firestore, на вкладку с данными, и нажмите Start collection. Идентификатор коллекции — teachers. Идентификатор документа — Ваша почта, та же самая, что на предыдущем шаге, знак в знак. Добавьте одно поле с именем name, тип string, значение — Ваше имя. Сохраните.
  7. Откройте вкладку Rules, удалите всё, что там есть, вставьте текст ниже и нажмите Publish. Менять в нём ничего не нужно.
Правила доступа
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isTeacher() {
      return request.auth != null
        && exists(/databases/$(database)/documents/teachers/$(request.auth.token.email));
    }

    match /teachers/{email} {
      allow read: if request.auth != null && request.auth.token.email == email;
      allow write: if false;
    }

    match /groups/{code} {
      allow read: if true;
      allow write: if isTeacher();
    }

    match /participants/{docId} {
      allow create: if request.resource.data.keys().hasOnly(['displayName', 'groupCode', 'platformId', 'createdAt'])
        && request.resource.data.displayName is string
        && request.resource.data.displayName.size() >= 2
        && request.resource.data.displayName.size() <= 40
        && exists(/databases/$(database)/documents/groups/$(request.resource.data.groupCode));
      allow read: if isTeacher();
      allow update, delete: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

Эти правила вставляются как есть и больше не открываются никогда. В них нет ни Вашей почты, ни кодов групп, ни других значений, которые пришлось бы подставлять. Всё, что меняется со временем, живёт в самой базе.

Читать список зарегистрировавшихся может только тот, чья почта лежит документом в коллекции teachers. Дописать себя туда через платформу нельзя, коллекция закрыта на запись, новые преподаватели добавляются только Вами и только в консоли. Проверки на то, что вошёл хоть кто-нибудь, здесь было бы мало, потому что завести себе аккаунт в Вашем проекте может любой.

Группы хранятся в коллекции groups и заводятся позже, на экране преподавателя. Зарегистрироваться можно только в ту группу, которая там есть, это проверяют правила. Добавили группу — она работает сразу, без правок правил и без переустановки платформы.

  1. В левом меню нажмите Settings и выберите General. Прокрутите страницу вниз до раздела Your apps и нажмите значок с угловыми скобками, это веб-приложение. Имя приложения любое, Firebase Hosting подключать не нужно, затем нажмите Register app.
  2. На экране появится блок firebaseConfig. Скопируйте его целиком в текстовый файл и сохраните под именем my-config.txt. Если файл потеряется, этот же блок всегда лежит в Settings, General, раздел Your apps.

  projectId: "my-course-2f41c",

Копируйте его целиком, вместе со словами const firebaseConfig = в начале и закрывающей фигурной скобкой с точкой с запятой в конце. Строки выше, которые начинаются со слова import или с двух косых черт, не нужны.

Значение apiKey в этом блоке — не пароль, а идентификатор проекта, поэтому он спокойно лежит в открытом коде сайта. Доступ к данным определяют правила.

Step 02

The database

Done once, before building. What you need at the end is a my-config.txt file holding the connection settings, and a teacher sign-in.

  1. Open console.firebase.google.com and sign in with a Google account.
  2. Click Create a project. Give it a plain name such as my-course. Analytics is not needed.
  3. In the left menu, under Product categories, open Databases & Storage and choose Firestore from the list that appears, in the NoSQL group. It must be Firestore and not Realtime Database, which is a different database. Click the button that creates the database. Choose production mode. Pick the region closest to you — it cannot be changed later.
  4. In the left menu, under Product categories, open Security and choose Authentication. Click the button that starts it, pick Email/Password in the list of sign-in methods and turn on the first switch. The second one, Email link, is not needed.
  5. Open the Users tab, click Add user, and enter your work e-mail and a password you use nowhere else. This is your teacher sign-in.
  6. Go back to Firestore, to the data tab, and click Start collection. The collection id is teachers. The document id is your e-mail, exactly the one from the previous step, character for character. Add one field called name, of type string, with your name as its value. Save.
  7. Open the Rules tab, delete everything in it, paste the text below and click Publish. Nothing in it needs changing.

These rules are pasted as they are and never opened again. They hold no e-mail of yours, no group codes, nothing you would have to substitute. Everything that changes over time lives in the database itself.

Only the person whose e-mail sits as a document in the teachers collection can read the list of registrations. Nobody can add themselves there through the platform, the collection is closed to writing, and new teachers are added by you alone, in the console. Checking merely that somebody is signed in would not be enough here, because anyone can create an account in your project.

Groups live in the groups collection and are created later, on the teacher screen. A learner can register only into a group that exists there, and the rules enforce it. Add a group and it works at once, with no edit to the rules and no redeployment of the platform.

Шаг 03

Правила для ИИ

Этот блок вставляется в начало каждого запроса, без изменений. Он удерживает механику отдельно от содержания и не даёт модели присылать куски, которые пришлось бы сращивать вручную.

Правила
ПРАВИЛА. Соблюдай их во всех ответах в этой переписке.

1. У платформы два файла. index.html — механика. content.js — содержание курса. В одном ответе присылай один файл, тот, который я назвал, и всегда целиком, с первой строки до последней.
2. Механика ничего не знает о конкретном курсе. Все заголовки, тексты, задания и пути к медиа она берёт из объекта COURSE, объявленного в content.js. В index.html не должно остаться ни одного учебного текста. Служебные надписи интерфейса — названия кнопок, заголовки экранов, сообщения об ошибках — наоборот, пиши прямо в index.html по-английски, в содержание они не выносятся.
3. Когда я прошу содержание, присылай только content.js и не трогай index.html. Когда я прошу правку механики, присылай только index.html.
4. Только чистые HTML, CSS и JavaScript. Без React, Vue, jQuery, npm, сборки и любых фреймворков. Стили внутри элемента style, скрипт внутри элемента script, оба в index.html. Элемент style ставь в head, а все элементы script последними внутри body, после всей разметки.
5. Сначала телефон. Страница должна работать на телефоне в вертикальном положении, без горизонтальной прокрутки.
6. Язык интерфейса — английский.
7. Никогда не используй символы стрелок в интерфейсе. Пиши словами — Next, Back, Continue, Check.
8. Основной текст не меньше 16 пикселей. Контраст текста к фону не ниже 4,5 к 1.
9. Всеми элементами можно пользоваться с клавиатуры, клавишами Tab и Enter.
10. Никогда не обозначай верный и неверный ответ только цветом. Всегда дублируй словами.
11. Изображения и звук бери только из папки assets по относительному пути, который задан в содержании. Ничего из интернета. Декоративную графику рисуй в SVG или средствами CSS.
12. Никогда не используй всплывающие окна браузера — alert, confirm и prompt. Любое сообщение и любой вопрос рисуй прямо на странице.
13. Всё, на что можно нажать, делай элементом button. Элемент a не используй вообще, адрес страницы не меняется никогда.
14. Никогда не присылай фрагмент, заплатку или указание вставить что-то самостоятельно.
15. Если ответ не помещается целиком, не сокращай код, не выбрасывай части и не пиши «остальное без изменений». Продолжай писать файл, пока он не кончится, а если ответ оборвётся, я попрошу продолжить.
16. В ответе только блок кода. Без пояснений до и после него.
Step 03

Rules for the AI

This block goes at the start of every request, unchanged. It keeps the mechanics apart from the content and stops the model sending pieces you would have to splice together by hand.

Rules
RULES. Apply all of these to every answer in this conversation.

1. The platform has two files. index.html holds the mechanics. content.js holds the course content. Send one file per answer, the one I named, and always in full, from the first line to the last.
2. The mechanics know nothing about any particular course. Every heading, text, task and media path comes from the COURSE object declared in content.js. Not one line of teaching text may stay in index.html. Interface wording, on the other hand — button labels, screen headings, error messages — is written straight into index.html in English and never moved into the content.
3. When I ask for content, send content.js only and leave index.html alone. When I ask for a change to the mechanics, send index.html only.
4. Plain HTML, CSS and JavaScript only. No React, Vue, jQuery, npm, build step or frameworks of any kind. The CSS inside a style element and the JavaScript inside a script element, both in index.html. Put the style element in the head and every script element last inside the body, after all the markup.
5. Mobile first. It must work on a phone held upright, with no horizontal scrolling.
6. The interface language is English.
7. Never use arrow characters in the interface. Use words such as Next, Back, Continue, Check.
8. Body text at least 16 pixels. Text contrast at least 4.5 to 1 against its background.
9. Every control must be usable with the keyboard alone, with Tab and Enter.
10. Never mark an answer right or wrong by colour alone. Always say it in words as well.
11. Take images and sound only from the assets folder, by the relative path given in the content. Nothing from the internet. Draw decorative graphics in SVG or with CSS.
12. Never use the browser's pop-up windows, that is alert, confirm and prompt. Draw every message and every question on the page itself.
13. Everything clickable is a button element. Never use an a element at all, and the page address never changes.
14. Never send a fragment, a patch, or an instruction to insert something myself.
15. If an answer does not fit, do not shorten the code, drop parts or write "the rest is unchanged". Keep writing the file until it ends, and if the answer is cut off I will ask you to continue.
16. Answer with the code block only. No explanation before or after it.

Запрос 1. Каркас

index.html
Ты разработчик интерфейсов. Я преподаватель и код читаю плохо, поэтому всё должно работать без моих правок.

Собери каркас платформы курса. Пришли index.html.

Требования к index.html.
1. Четыре экрана, которые показываются по одному — Welcome, Registration, Module, Finish. Переключение делай в JavaScript, скрывая и показывая секции. Не создавай отдельных страниц и никогда не меняй адрес страницы. Элемент a не используй вообще, всё, на что можно нажать, делай элементом button.
2. Подключи content.js обычным тегом script. Оба тега script поставь последними внутри body, после всей разметки, сначала content.js, потом твой скрипт. К содержанию обращайся прямо по имени COURSE, а наличие файла проверяй строкой typeof COURSE === 'undefined'. Шаг 02

Юниты, подразделы, блоки

Курс состоит из юнитов, юнит из подразделов, подраздел из блоков. Блок это кирпич содержания, и типов блоков девять.

Что можно положить в подраздел

  • Текст четырёх видов, инструкция, текст для чтения, правило в рамке и вопросы для обсуждения. Жирное и курсив ставятся звёздочками.
  • Картинка, одна или несколько в ряд, с подписью и описанием для незрячих.
  • Аудио и видео. Видео встраивается ссылкой на Rutube или другой сайт, аудио лежит файлом рядом с курсом.
  • Карточки со словом, транскрипцией, переводом и примером. Слова карточек считаются словарём юнита.
  • Упражнение одного из пяти типов, о них следующий шаг.
  • Преподавательская заметка. Её видите только вы, в книге студента её нет. Туда удобно складывать цели, скрипты аудио и комментарии к ключам.

Порядок блоков меняется стрелками вверх и вниз, блок копируется и удаляется кнопками рядом. Номера упражнений проставляются сами.

Нажимайте Save в конструкторе почаще. Пока вы не нажали, изменения живут только в этой вкладке. После сохранения они сразу уходят в базу, и обучающиеся увидят их при следующем открытии страницы.

Step 02

Units, sections, blocks

A course is made of units, a unit of sections, a section of blocks. A block is a brick of content, and there are nine kinds of brick.

What can go into a section

  • Text of four kinds: an instruction, a reading text, a rule in a box and questions to discuss. Bold and italics are set with asterisks.
  • A picture, one or several in a row, with a caption and a description for screen readers.
  • Audio and video. Video is embedded by a link to Rutube or another site; audio sits as a file next to the course.
  • Flashcards with the word, its transcription, a translation and an example. The words on the cards count as the vocabulary of the unit.
  • An exercise of one of the five kinds; the next step is about them.
  • A teaching note. Only you see it; it is not in the student's book. A good place for aims, audio scripts and comments on the keys.

The order of blocks is changed with the up and down arrows, and a block is copied or deleted with the buttons beside it. Exercises are numbered by themselves.

Click Save in the builder often. Until you do, the changes live only in that tab. Once saved they go straight to the database, and the learners see them the next time they open the page.

Шаг 03

Упражнения и ключи

Пять типов упражнений. У четырёх есть ключ, и оболочка проверяет их сама; пятый проверяете вы.

  • Пропуск. Предложение с пропуском и ответ. Если правильных ответов несколько, они пишутся через точку с запятой, и засчитывается любой.
  • Выбор из списка. Тот же пропуск, но вместо поля выпадающий список. Правильный вариант помечается звёздочкой перед ним.
  • Выбор ответа. Вопрос и варианты A, B, C. Правильный тоже со звёздочкой.
  • Сопоставление. Общий список вариантов сверху и пункты, к каждому из которых выбирается буква.
  • Открытый ответ. Письмо, перевод, свои предложения. Ключ здесь это образец ответа, который видите только вы, а баллы и комментарий вы ставите руками в Student work.

Что решается у каждого упражнения

  • Когда показывать результат. Либо вы нажимаете «Check this exercise now» над упражнением, и группа сразу видит проверку, либо результаты открываются вместе со всем юнитом.
  • Сколько баллов за пункт у открытого ответа и сколько слов в нём минимум.
  • Без ключа. Опрос или мнение, где любой ответ верный и ничего не считается.

Ключи хранятся отдельно от того, что получают обучающиеся: в книгу студента уходит юнит без ответов. Поэтому ключи можно писать прямо в конструкторе и не бояться, что их найдут в коде страницы.

Step 03

Exercises and keys

Five kinds of exercise. Four of them have a key and the shell checks them itself; the fifth you check yourself.

  • Gap fill. A sentence with a gap and the answer. When several answers are right, they are written with semicolons between them and any of them counts.
  • Choose from a list. The same gap, but a dropdown instead of a field. The right option is marked with an asterisk in front of it.
  • Multiple choice. A question with options A, B, C. The right one carries an asterisk too.
  • Matching. One list of options at the top and items, each of which takes a letter.
  • Open answer. Writing, translation, sentences of one's own. The key here is a model answer that only you see, and you give the points and the comment by hand in Student work.

What is decided for every exercise

  • When the result is shown. Either you click “Check this exercise now” above it and the group sees the marking at once, or the results open together with the whole unit.
  • How many points an item of an open answer is worth, and how many words it needs at least.
  • No key at all for a survey or an opinion, where any answer is right and nothing is counted.

The keys are kept apart from what the learners receive: the student's book gets the unit without the answers. So the keys can be written straight into the builder, with no fear of someone finding them in the code of the page.

Шаг 04

Группа, выдача, проверка

  1. Группа. Teacher's Edition, Groups & students. Код группы придумываете вы, например ENG101, и даёте его обучающимся. Регистрация без существующего кода не проходит.
  2. Выдача. Access & results, строка юнита, кнопка открытия для группы. Пока юнит закрыт, в книге студента его нет.
  3. Работа. Ответы сохраняются сами, пока обучающийся печатает. Под каждым упражнением есть кнопка Done, а весь юнит сдаётся кнопкой Submit.
  4. Проверка по одному упражнению. Откройте юнит в Teacher's Edition и нажмите «Check this exercise now» над нужным упражнением. Группа сразу увидит, что верно и что нет.
  5. Проверка всего юнита. Access & results, кнопка Release. Юнит закрывается, баллы и правильные ответы открываются всей группе разом.
  6. Открытые ответы. Student work, выберите обучающегося, поставьте баллы и напишите комментарий, нажмите Save marks. Кнопка Return for revision возвращает работу на доработку.
  7. Тест на время. Делается в конструкторе как отдельная часть юнита, открывается группе и закрывается по кнопке.
Step 04

Group, access, checking

  1. The group. Teacher's Edition, Groups & students. The group code is yours to invent, say ENG101, and you give it to the learners. Registration without an existing code does not go through.
  2. Access. Access & results, the row of the unit, the button that opens it for the group. While a unit is closed it is not in the student's book at all.
  3. The work. Answers save themselves as the learner types. Under every exercise there is a Done button, and the whole unit is handed in with Submit.
  4. Checking one exercise. Open the unit in Teacher's Edition and click “Check this exercise now” above the exercise you mean. The group sees at once what is right and what is not.
  5. Checking the whole unit. Access & results, the Release button. The unit closes and the points and correct answers open for the whole group at once.
  6. Open answers. Student work, choose a learner, give the points, write a comment and click Save marks. The Return for revision button sends the work back.
  7. A timed test. It is made in the builder as a part of the unit of its own, opened for the group and closed with a button.
Шаг 05

Юнит с помощью ИИ

Юнит можно написать в переписке с моделью и загрузить файлом, а не набирать по блоку руками.

  1. Teacher's Edition, Import and export, кнопка Copy the prompt. В запросе уже описан формат файла и все типы блоков.
  2. Вставьте запрос в переписку с любой моделью и допишите своё, тему юнита, уровень, для кого и сколько упражнений каждого типа.
  3. Ответ модели, то есть файл .json или блок кода, вставьте в поле импорта на той же странице и нажмите Import. Ошибку импорта можно скопировать обратно в переписку, модель её исправит.
  4. Откройте полученный юнит в конструкторе и прочитайте целиком. Проверьте ключи, факты и уровень. Модель ошибается, а отвечаете за материал вы.

Не вставляйте в переписку с моделью имена и работы обучающихся. В запросе для конструктора их и нет, он про содержание юнита.

На той же странице лежит выгрузка. Export сохраняет весь курс одним файлом, это ваша резервная копия; храните её на своём компьютере, а не в репозитории. Юнит выгружается и в Word, отдельно для обучающихся и отдельно для преподавателя с ключами.

Step 05

A unit written with an AI

A unit can be written in a chat with a model and imported as a file, instead of being typed block by block.

  1. Teacher's Edition, Import and export, the Copy the prompt button. The request already describes the format of the file and every kind of block.
  2. Paste the request into a chat with any model and add your own part: the topic of the unit, the level, who it is for and how many exercises of each kind.
  3. Paste the model's answer, that is the .json file or the block of code, into the import field on the same page and click Import. An import error can be copied back into the chat, and the model will fix it.
  4. Open the unit you get in the builder and read all of it. Check the keys, the facts and the level. A model makes mistakes, and the material is your responsibility.

Do not paste the names or the work of learners into a chat with a model. The builder's prompt holds none of that: it is about the content of a unit.

The same page holds the export. Export saves the whole course as one file, which is your backup; keep it on your computer rather than in the repository. A unit also exports to Word, once for the learners and once for the teacher with the keys.

Шаг 06

Картинки и аудио

  1. На своём компьютере положите файл в папку docs/media внутри папки курса. Удобно завести внутри папку на юнит, например docs/media/u1.
  2. Имя файла задайте строчными латинскими буквами без пробелов, например u1-dialogue.mp3. Пробелы и кириллица дают ссылки, которые не открываются.
  3. В репозитории нажмите Add file, Upload files и перетащите папку media целиком. GitHub сохранит её устройство.
  4. В конструкторе в блоке картинки или аудио впишите путь без docs, например media/u1/dialogue.mp3. Проигрыватель появится сам.

Кнопки для создания пустой папки на GitHub нет, и это не недосмотр. Папка в репозитории существует только вместе с файлами внутри, поэтому media/u1 появляется в тот момент, когда в неё попадает первый файл.

Step 06

Pictures and audio

  1. On your own computer put the file into the docs/media folder inside the course folder. A folder per unit inside it, say docs/media/u1, keeps things tidy.
  2. Name the file in lower-case Latin letters with no spaces, for example u1-dialogue.mp3. Spaces and non-Latin letters give links that do not open.
  3. In the repository click Add file, Upload files and drag the whole media folder in. GitHub keeps its structure.
  4. In the builder, in a picture or audio block, write the path without docs, for example media/u1/dialogue.mp3. The player appears by itself.

GitHub has no button for creating an empty folder, and that is not an oversight. A folder in a repository exists only together with the files inside it, so media/u1 appears at the moment the first file lands in it.
